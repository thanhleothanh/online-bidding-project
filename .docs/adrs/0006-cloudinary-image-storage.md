# ADR-0006: Cloudinary for Image Storage

## Status

Accepted

## Context

Auctions and reports require image uploads (product photos, evidence images). The application needs a solution for:

- Storing images persistently
- Serving images via CDN for performance
- Generating thumbnails and handling transformations
- Deleting images when items or reports are removed

Self-hosted storage (local filesystem or S3) requires infrastructure management. A managed service reduces operational complexity.

## Decision

Use Cloudinary as the image storage backend:

1. Add `com.cloudinary:cloudinary-http44:1.39.0` dependency
2. Configure Cloudinary credentials via environment variables or Spring properties
3. Upload images via `Cloudinary.uploader().upload(file, options)`
4. Delete images via `Cloudinary.uploader().destroy(publicId, options)`
5. Store `publicId` in the database (`ItemImage.publicId`) to enable deletion
6. Use `ObjectUtils.emptyMap()` for default upload options

## Consequences

- **Positive**: No infrastructure management for image storage
- **Positive**: Built-in CDN, automatic format optimization, and thumbnail generation
- **Positive**: Simple API for upload and deletion
- **Negative**: External service dependency; images are unavailable if Cloudinary is down
- **Negative**: Vendor lock-in; migration to another provider requires re-uploading images
- **Neutral**: Image URLs are returned by Cloudinary, not generated by the application
